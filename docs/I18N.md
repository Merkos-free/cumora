# Локализация интерфейса

Русская версия Cumora поставляется с тремя языками интерфейса:

- русский (`ru`) — основной язык этого форка;
- английский (`en`);
- упрощённый китайский (`zh-CN`).

Язык выбирается отдельно на каждом устройстве: **Настройки → Язык** на компьютере и **Вы → Язык** на телефоне. Изменение применяется сразу, без перезагрузки приложения. На первом запуске всегда выбирается русский, даже если системный язык браузера английский. После ручного переключения выбор сохраняется в `localStorage`.

## Как всё устроено

Зависимости для i18n не используются. Основные файлы:

| Файл | Назначение |
|---|---|
| `src/lib/i18n.ts` | хранилище текущего языка, поиск строк и подстановка переменных `{name}` |
| `src/locales/en.ts` | английский каталог и источник всех допустимых ключей |
| `src/locales/zh-CN.ts` | китайский каталог |
| `src/locales/ru.ts` | сборка полного русского каталога |
| `src/locales/ru/*.ts` | разговорные русские переводы по разделам продукта |
| `server/src/__tests__/ru-locale.test.ts` | проверка, что русский перевод не пропустил ни одного ключа |

Английский объект `en` задаёт тип ключей для всех остальных языков. Опечатка или выдуманный ключ ловится TypeScript. Русский каталог дополнительно проверяется тестом полноты: если в `en.ts` появился новый ключ без русского значения, `npm test` падает и показывает список пропусков.

## Использование в компоненте

```tsx
import { useT } from '@/lib/i18n'

function Greeting({ name }: { name: string }) {
  const t = useT()
  return <div>{t('common.greeting', { name })}</div>
}
```

`useT()` — React-хук. Компонент автоматически перерисуется после смены языка. Для обработчика события или кода на уровне модуля используется нерективная функция `t()`.

Данные, объявленные на уровне модуля, должны хранить **ключ сообщения**, а не готовую строку:

```tsx
const tabs: Array<{ key: string; label: MessageKey }> = [
  { key: 'profile', label: 'me.tab.profile' },
]
```

`key` отвечает за состояние и маршрутизацию, поэтому не меняется вместе с языком. Переводится только `label`.

## Как добавить новую строку

1. Добавьте ключ и английский текст в `src/locales/en.ts`.
2. Используйте `t('area.thing')` в компоненте.
3. Добавьте естественный русский вариант в подходящий файл `src/locales/ru/`.
4. Добавьте китайский вариант в `src/locales/zh-CN.ts` либо осознанно оставьте английский fallback для китайского языка.
5. Запустите:

```bash
npm test
npm run typecheck
```

Ключи именуются как `раздел.элемент`: `nav.`, `auth.`, `me.`, `mobileMe.` и так далее. Общие подписи находятся под `common.`.

### Принципы русского текста

- Переводим смысл, а не порядок английских слов.
- Пишем так, как человек сказал бы это в обычном рабочем чате.
- Убираем канцелярит: «попробовать ещё раз», а не «осуществить повторную попытку».
- Сохраняем переменные `{name}`, `{count}`, HTML-теги и управляющие символы.
- Названия продуктов и движков — Cumora, Codex, Claude Code, OpenCode, BYOA — не переводим.
- Для действия используем понятный глагол: «Сохранить», «Открыть», «Убрать из команды».
- Длинную техническую подсказку сначала объясняем человеческим языком, затем оставляем точные имена переменных и команд.

## Как добавить ещё один язык

1. Создайте `src/locales/<код>.ts` с типом `Partial<Record<keyof typeof en, string>>`.
2. Импортируйте словарь в `src/lib/i18n.ts`.
3. Добавьте код в объединение `Locale`, объект `DICTS` и список `LOCALES`.
4. Название в поле `label` напишите на самом языке: пользователь ищет «Русский» или `简体中文`, а не английское название.
5. При необходимости измените логику первого запуска в `detectLocale()`.

Переключатель языка строится автоматически из `LOCALES`; отдельное изменение интерфейса не требуется.

## Что не входит в UI-каталог

Ответы агентов, автоматические сводки, тексты писем и другие сообщения, которые создаёт модель, зависят от серверных системных промптов. В русском форке общие правила речи находятся в `server/src/agents/agent-voice.ts`, а стартовые характеры — в `server/src/onboardCompany.ts`. Их нужно проверять отдельно от интерфейсного словаря.
